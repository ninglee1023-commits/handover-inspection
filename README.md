# 竣工驗收記錄 (handover-inspection)

離線 iPad 網頁程式：圖紙上點選位置 → 拍照 → 標記箭頭／圈選 → 自動帶出座／層／房間／Grid → 導出 Word 報告。

- 純靜態網頁，放上 GitHub Pages 即可使用；首次開啟後可離線。
- 資料儲存在 iPad Safari 的 IndexedDB，請「加入主畫面」並定期備份（完整、只限新增記錄，或按驗收批次每次驗收一個 ZIP）。
- 設定只填檢查人員名字，記錄編號以名字開頭（陳大文-001）。匯入同事的備份時，每個批次自成一個「名字-批次名稱」的批次（同名自動加（2）），不會自動合併；看過後在「驗收批次 → 合併批次」勾選多個批次，輸入新名稱合併，一次出報告。
- 函式庫：pdf.js 3.11.174、docx 8.5.0（已放在 lib/，不需外部 CDN）。
- 兩套圖紙：頂部「建築｜渠務」切換。建築 GBP（gbp/plans.pdf + gbp/mapping.json）及渠務圖（gbp/drainage.pdf 第 8–14、16–24 頁 + gbp/drainage-mapping.json）各自有圖紙清單、驗收批次、編號和報告。渠務圖包第一次切換時下載（約 36 MB）。
- 建築 gbp/plans.pdf：全部用 13th GBP Amd Approval Drawing（20260708）。第 1–15 頁為平面（原檔第 3–9、13–20 頁；第 7 頁 A/GBP/09 為整層 3/F，包括 T1、T2、T3、T5，原檔抽頁在 gbp/src/gbp13_AGBP09.pdf），第 16–21 頁為立面 A/GBP/21（平台 Elevation 1–4）及 A/GBP/25、26、26.1、27、28（塔樓 Elevation 5–18；原檔抽頁在 gbp/src/gbp13_elevations.pdf）。v0.9.0 曾換上 14th GBP Amd Draft，v0.9.4 改回 13th：換過的圖紙保留原 id，mapping 內的 `xf` 把在 14th 圖上打的點搬回 13th 圖（記錄以 `pf` 標記所屬版本，`unset` 指明沒有 pf 的記錄屬哪一版；匯入舊備份或舊相片時一樣會轉換）。從圖紙包拿走的圖紙，如果沒有記錄就會從 iPad 刪除。
- B3–B1 車位：每個車位（住宅 R、V，公眾 P，商業 C，電單車 RM／PM／CM，上落貨位 LG／HG）都是一個區域，在車位內點選，區域欄就會填「Parking Space R40」、「Motor Cycle Parking Space PM12」、「Loading/Unloading Bay HG04」等。範圍及編號取自 GBP 圖上的車位線條及編號字（B3 132 個、B2 180 個、B1 25 個）；B2 的 LG01–LG03 沿用原有註明座號的區域。
- 建築圖紙清單分「平面圖／立面圖」（渠務不設立面）。建築立面以 `lv` 樓層線取代樓層選擇：點選位置下方最近的樓層線就是該層；軸線（gx）取自立面上的軸線圈，立面編號記在區域欄。塔樓立面（3/F 以上）另有單位格：由立面與平面共用的軸線求出比例及位移（平面 1:100 → 立面 1:200，忽略拐線偏移的軸線圈），再從觀看方向對平面單位範圍投射，最先碰到的單位就是該段外牆的 flat；每個樓層段（3/F、標準層、T5 5–17/F 及 18–30/F）各自計算。
- 分判回復：把合併後的批次「按驗收批次備份」發給各分判；分判匯入後按頂部「篩選」只顯示自己的點（圖上、記錄清單及上一項／下一項一併篩選，本機會記住），逐點按「回復」拍完成照，再按「導出此批次的回復包」發回（只含回復及完成照，不含完成前照片）。匯入時按記錄內部 ID 自動對回原本的項目，與編號無關。如果分判同時改了描述、分判、編號或位置，匯入後會彈出窗口逐項讓你確認，沒有勾選的保留你的版本。
- 篩選（頂部「篩選」）：分區（Podium＝B3–2F、T1、T2、T3、T5）及分判可同時選，圖上、記錄清單及上一項／下一項一併篩選。「圖紙」清單及「樓層」選擇旁有小圓點（不篩選時按整個批次，篩選後只計所選項目）：紅點＝該圖／該層有未回復的項目，綠點＝全部已回復，不用逐張圖打開找。
- 不需執修及審查（v0.10.15–17）：分判認為某項不需執修，在回復處按「此項不需執修？」寫原因（必須填寫）後提交，該項變成「不需執修・待審查」（圖上橙色點）。管理員（在線批次的管理員；離線時任何不是提交人的人）在同一處看到原因，可「認可不需執修」或「駁回」（駁回必須寫意見），駁回後該項彈回「未回復」，分判可以執修拍照（變成已完成）或再說明。每一步（提交、認可、駁回）都保留在「不需執修・溝通記錄」，報告的回覆欄亦會列出。篩選的回復狀態有「不需執修」及「不需執修・待審查」，選後者可用上一個／下一個逐項審查。
- 各分判完成情況（v0.10.18）：「篩選」面板最下面列出目前批次（及所選分區）每個分判的「已完成／總數」，按「複製」即可貼上發出。管理員認可的「不需執修」計入已完成，待審查的另外註明；一項有多個分判時每個分判各計一次。
- 刪除本地批次（v0.10.19）：「驗收批次」面板下面「刪除本地批次」選擇批次，按兩次確認，連同批次內全部記錄及相片從這部機刪除（不能復原，確認時會顯示有幾項未備份）。在線批次不在此刪除。一個圖紙組的批次全部刪除後，自動留一個空的「第1次驗收」。
- 在線回復（v0.10）：把最終清單上載到 Firebase 並鎖定，分判／同事開連結即時回復。在「驗收批次」最下面按「發佈並鎖定此批次」：記錄、完成前相片（縮細至約 1600px）上載後即鎖定：其他人都不能再加點、刪點，或改描述、分判、編號、位置；只有管理員（發佈那部機，或任何輸入過發佈密碼的機）可照常修改、加點、刪點、整理編號、併入批次，改動即時同步給所有人。之後「分享連結」發出（亦有二維碼）；對方開連結就載入這張清單（同一程式，無需安裝），用「篩選」選自己的分判，逐點「拍回復照片」，相片即時上載，所有開着這張清單的 iPad／手機（包括你的）即時看到綠點及回復照片。沒有訊號時相片先存在本機，頂部批次按鈕顯示「↑數目」，有訊號後自動補傳；「↓數目」是仍在下載的相片。回復報告照舊在「導出」生成。不用連結也可以加入：任何人開程式，「驗收批次」面板的「在線清單」會列出已發佈的清單，按「加入」即可。管理員在同一面板可以把另一個批次「併入」這張在線清單，記錄及相片會上載，所有人即時看到。
  - 只用 Firestore（相片每張一個文件，不用 Cloud Storage），免費 Spark 計劃即可（1 GB 容量，約 3000–4000 張相）。
  - Firebase 項目 `handover-inspection`（Spark 免費計劃，Firestore 在 asia-east2 香港，Authentication 只開 Anonymous），config 已在 `live.js` 的 `LIVE_CFG`。改了 `firebase/firestore.rules` 要到 Firestore → 規則 貼上並發布。管理員：發佈那部機，或在「驗收批次」輸入發佈密碼按「成為管理員」的任何機；換密碼後，舊密碼登記的機（發佈機除外）即失去管理員權限。
  - 多人回復：不用登入，每部機的瀏覽器有自己的匿名 ID，回復按人分開存放（`replies/{記錄}_{ID}`）。每人只可改或刪自己的回復照片及文字（伺服器規則限制），發佈人可刪任何人的回復照片。同一項有幾個人回覆文字時，報告內以「名字：內容；…」合併。發佈人的「驗收批次」面板列出回復人員：名字、ID 頭 6 位、回復項數、相片數、最後時間；同名不同 ID 即不同機。ID 跟瀏覽器走，換機、換瀏覽器或清除網站資料就會變成新 ID。
  - 「驗收批次」分兩部分：上面「在線批次」（雲端，所有人同步：本機已加入的及雲端可加入的），下面「本地批次」（只在這部機）。除上傳及管理在線批次外，所有功能人人照用。管理員（在最底按細字「管理員登入」輸入發佈密碼）才會看到：本地批次的「上傳為在線批次」（上傳後自動移到在線批次），以及在線批次的修改、併入、改名、分享連結、回復人員和「刪除」（在線批次每一行都有）。刪除只是移到「回收箱」（在線批次列表下面，管理員才見）：各部機已有的記錄變回本地批次，雲端的記錄、回復及相片全部保留，沒有期限，可以按「還原」（各人重新加入，會回到原本的批次）；只有在回收箱按「永久刪除」才會真正清走。回收箱的資料仍佔 Firebase 的免費容量（約 1 GB）。
  - 發佈密碼：每部機第一次發佈要輸入一次（密碼不在程式碼內）。Firestore 的 `pubkeys` 集合存放密碼的 SHA-256（`handover-inspection|密碼`）作文件 ID；換密碼＝新增新雜湊的文件、刪除舊文件，舊密碼登記過的機即時失去發佈權（已發佈的清單照常可修改）。
